# Teams Transcript Summary

Given one Teams transcript file, produce two files next to it: a cleaned transcript (`<name>.txt`) and a Markdown summary (`<name>-summary.md`).

## Defaults

- **filename** — the base name of the input file (strip the extension), used for both outputs.
- **user** ("Generated by") — `Daniel Macuare`, unless the requester says otherwise.
- **date** ("Generated on") — today's date (the date this skill runs), **not** any date embedded in the meeting filename. A transcript from an old meeting still gets today's generation date.
- **output location** — same directory as the input file, unless told otherwise.

## Step 1: Check before overwriting

Teams/OneDrive environments often already contain a file at the exact output path — sometimes a bot-generated transcript/summary of a *different* meeting that happens to share a similar name, or leftovers from a prior manual run. Before writing either output file:

1. If nothing exists at that path, proceed.
2. If a file exists and its first line is exactly `File generated by AI from the source document:` (i.e. this skill produced it before), overwrite it freely — that's expected regeneration.
3. If a file exists and does **not** start with that line, stop and ask the requester how to proceed (overwrite, use a different filename, or inspect first) rather than silently clobbering it. Show them what the existing file actually contains before they decide.

## Step 2: Generate `<filename>.txt`

**For a `.vtt` input**, run the bundled script — do not hand-parse the VTT yourself and do not `Read` the raw `.vtt` into context first (these files run into the thousands of lines; reading the raw file wastes context for no benefit since the script handles it deterministically):

```bash
python3 scripts/vtt_to_txt.py <input.vtt> <output.txt> \
  --source-name "<original filename>" \
  --generated-by "Daniel Macuare"
  # --generated-on defaults to today; pass it explicitly only if told a different date
```

The script strips `WEBVTT` headers, cue IDs (e.g. `45211125-391e-4a58-a74c-58f7b66e9b05/422-1`), and per-cue timestamp ranges; merges consecutive same-speaker cues into one turn; and keeps only the start timestamp of each turn plus the verbatim text (filler words and false starts included — do not clean up the speech itself). It also writes the three-line header automatically. Output format per turn:

```
[HH:MM:SS] Speaker Name: verbatim merged text
```

**For a `.docx` input**, there is no script (Teams' docx export structure varies more than `.vtt`, and doesn't always retain per-speaker timestamps). Convert it to text first (e.g. `textutil -convert txt` on macOS, or read it directly if short), then apply the same rules by hand: identify each speaker turn, keep only the first timestamp for that turn if one is present in the source (omit the timestamp entirely if the docx export doesn't carry per-turn times — don't fabricate one), strip any transcript IDs, and merge consecutive same-speaker paragraphs. Prepend the same three-line header (see below) before writing.

**Header block** (identical for both output files, three lines then a blank line):

```
File generated by AI from the source document: <original filename>
Generated on: <YYYY-MM-DD>
Generated by: <user>
```

## Step 3: Generate `<filename>-summary.md`

Read the *cleaned* `<filename>.txt` produced in Step 2 (not the raw source) and produce a Markdown summary, capped at **300 lines total including the header**. Structure:

```markdown
File generated by AI from the source document: <original filename>
Generated on: <YYYY-MM-DD>
Generated by: <user>

## Summary

<2-4 sentences: what the meeting was about and where things stand>

## Meeting Notes

<topic-grouped notes on what was actually discussed, with enough detail to
be useful without re-reading the transcript>

## Actions

<action items, each with an owner if the transcript names one>

## Agreements/Disagreements

<what was explicitly agreed, and any live disagreements or unresolved
tension between speakers — don't flatten a disagreement into a false
consensus>

## Others

<anything notable that doesn't fit the above — e.g. scheduling logistics,
attendee notes. Omit this section entirely if there's nothing left over>
```

If content threatens to exceed 300 lines, trim in this order: drop "Others" first, then condense "Meeting Notes" detail — never cut content from "Actions" or "Agreements/Disagreements," since those are the most consequential to preserve.

Write plain, factual sentences sourced only from what's in the transcript — don't infer intent or outcomes the speakers didn't state.
